# FR-11: Visual-Based Localization

## Requirement
> The system shall periodically establish the UAV's absolute global position, while
> GNSS is denied, by matching the live downward-camera image against a
> geo-referenced reference image database, recovering a global pose
> (latitude, longitude, altitude), and forwarding that estimate to PX4 EKF2 as
> `VISION_POSITION_ESTIMATE`.

## Summary
- The canonical runtime path is `src/vns/core/vns_node.py` -> `VnsRuntime` ->
  `VisualLocalizer`.
- The live camera source for simulation is
  `/vns_drone/downward_camera/image_raw`.
- PX4 external-vision injection for full simulation uses MAVSDK on
  `udp://:14540`.
- Reference-database entry altitude remains the **ground / terrain MSL datum**
  under each tile, not the camera capture altitude.

## Dependencies
- `FR-4` — sensor acquisition for the downward camera, IMU, GPS, and ground truth.
- `FR-9` — coarse retrieval and geometric verification support the image match path.
- `FR-12` — GNSS-denied blending / fallback behavior consumes the visual fix.

## Acceptance Criteria
1. **[Guarded]** `vns_node` fails early with a clear actionable error if the ROS 2
   Python environment is incompatible with `cv_bridge` (for example NumPy 2.x on
   ROS 2 Humble), instead of crashing later in the first camera callback.
2. **[Met]** In a compatible Ubuntu 22.04 / ROS 2 Humble environment, the node can
   subscribe to `/vns_drone/downward_camera/image_raw` and process frames without
   `_ARRAY_API not found` or equivalent ABI failures.
3. **[Met]** The active full-simulation MAVSDK connection string is
   `udp://:14540`, matching PX4 SITL's onboard-computer UDP port; `14550`
   remains the QGroundControl / GCS listener.
4. **[Met]** Runtime logs state which MAVLink connection string is being used,
   whether the flight controller connected, and whether the
   `VISION_POSITION_ESTIMATE` send path is active.
5. **[Met]** Every reference-database entry altitude matches the simulation
   ground datum (`geo_reference.origin_altitude` ~550 m MSL), not legacy
   580–620 m capture altitudes.
6. **[Workflow Implemented]** The repository contains a clear ROS 2 Humble capture
   flow for real Gazebo-rendered downward-camera frames that writes:
   - JPG images under `simulation/database/images/gazebo/`
   - `database_index.yaml` metadata with source provenance
   - enough data to rebuild `simulation/database/qau_campus.vnsdb`
7. **[Met]** Synthetic reference imagery remains available only as an explicit
   offline/test baseline and is labeled `source_type: synthetic` so it cannot be
   mistaken for real Gazebo camera captures.
8. **[Pending Local Run]** After rebuilding `simulation/database/qau_campus.vnsdb`
   from Gazebo-captured frames, a GNSS-denied full simulation can localize live
   camera frames, switch to `VISION` or `DR` as appropriate, and continue sending
   vision estimates to PX4.

## Test Plan

### Unit / Static Checks
- `tests/test_ros_env.py` — NumPy / `cv_bridge` compatibility messages and success path.
- `tests/test_simulation_config.py` — active simulation MAVLink port is `udp://:14540`.
- `tests/test_reference_image_provenance.py` — DB build path preserves synthetic/Gazebo provenance metadata.
- `tests/test_db_altitude_consistency.py` — ground-datum altitude regression guard.

### Runtime / Offline Checks
- `python3 simulation/scripts/check_ros2_python_env.py`
- `python3 simulation/scripts/test_run.py`
- `python3 -m pytest tests/ -q`

### Manual ROS2 / Gazebo / PX4 Checks
1. Run `python3 simulation/scripts/check_ros2_python_env.py`.
2. Run `ros2 launch vns localization_test.launch.py headless:=true` and verify
   `/vns/vision_pose` publishes without camera-path crashes.
3. Run `ros2 launch vns full_simulation.launch.py headless:=true` and verify logs
   show `udp://:14540`, successful flight-controller connection, and an active
   vision-estimate send path.
4. Toggle GPS denial and verify the runtime transitions from GNSS-primary to
   `VISION` / `DR`.
5. Capture real Gazebo frames, rebuild `simulation/database/qau_campus.vnsdb`,
   rerun the full simulation, and verify live frames match the rebuilt database
   instead of failing with `no_geometric_match`.
