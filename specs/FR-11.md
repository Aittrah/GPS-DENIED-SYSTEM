# FR-11: Visual-Based Localization

## Requirement
> The system shall periodically establish the UAV's absolute global position, while
> GNSS is denied, by matching the live downward-camera image against a geo-referenced
> reference image database and recovering a global pose (latitude, longitude, altitude)
> from the matched reference tile.

## Rationale
In a GNSS-denied environment the UAV's only source of absolute (drift-free) global
position is visual matching against a database of geo-tagged reference imagery. The
recovered pose is fused into the PX4 EKF2 as a `VISION_POSITION_ESTIMATE`. Pose
recovery converts pixel displacement between the live frame and the matched tile into
metres using the camera's height above the imaged ground:
`height = drone_altitude_MSL - entry.altitude` (`src/vns/vision/pose_recovery.py`).
For this scale term to be physically correct, `entry.altitude` **must be the ground /
terrain MSL datum under the tile**, identical to the simulation `geo_reference`
origin altitude (~550 m MSL). If reference tiles instead carry *camera capture*
altitudes (e.g. 600–620 m), the height term is under-estimated, displacement-to-metres
is compressed, and off-center pose recovery is systematically biased toward the
matched tile (worst case ~29 % at the 240 m AGL demo altitude).

## Acceptance Criteria
1. Given a live frame that matches a reference tile, the localizer returns a global
   pose (lat, lon, alt) whose horizontal error is bounded and **unbiased** for
   off-center matches (no systematic pull toward the tile centre). _(pending
   end-to-end simulation validation)_
2. **[Met]** Every reference-database entry's `altitude` is consistent with the
   configured simulation `geo_reference.origin_altitude` (~550 m MSL ground datum) —
   i.e. within a tight band around 550 m, and never the 600–620 m capture-altitude
   values.
3. **[Met]** The built `qau_campus.vnsdb` embeds the corrected altitudes (the runtime
   loads the built DB, not the YAML index), and a regression test fails if any entry
   drifts back outside the ground-datum band.
4. **[Met]** The packaged localizer can select its coarse retrieval backend from
   config, including BoVW retrieval in addition to FLANN/LSH.
5. **[Met]** FLANN/LSH retrieval remains available as the default packaged
   runtime path and as the explicit fallback mode.
6. **[Met]** Localizer output remains compatible with the existing geometric
   verification and pose-recovery stages regardless of which coarse retrieval
   backend is selected.
7. **[Met]** Unit tests cover both retrieval modes in the packaged
   `VisualLocalizer` and `VnsRuntime` paths.
8. **[Met]** The ROS packaged runtime (`src/vns/core/vns_node.py` ->
   `VnsRuntime` -> `VisualLocalizer`) can use the configured retrieval mode
   without depending on `simulation/scripts/visual_navigation.py`.

## Dependencies
FR-10 (Reference Image Database) — the database tiles must be geo-tagged with a
correct ground-datum altitude for this requirement's pose recovery to be unbiased.

## Linked Source Files
- `src/vns/vision/localizer.py` — orchestrates retrieval → verification → pose recovery.
- `src/vns/vision/retrieval.py` — packaged FLANN/LSH and BoVW retrieval backend selection.
- `src/vns/vision/bovw_retrieval.py` — reusable BoVW histogram retrieval implementation.
- `src/vns/vision/pose_recovery.py` — `displacement_to_pose()`; consumes `entry.altitude`
  as the ground datum in `height = altitude - entry.altitude`.
- `src/vns/database/reference_db.py` — loads the geo-tagged `.vnsdb` entries.
- `src/vns/core/runtime.py` — packaged runtime that constructs and uses `VisualLocalizer`.
- `src/vns/core/vns_node.py` — ROS entrypoint that routes configuration into the packaged runtime.
- `simulation/database/images/database_index.yaml` — build input; per-entry altitudes.
- `simulation/database/qau_reference_metadata.yaml` — human-authored reference-point spec.
- `simulation/database/qau_campus.vnsdb` — built database the runtime loads.
- `simulation/config/simulation.yaml` — `geo_reference.origin_altitude` ground datum (550 m).

## Test Plan

### Unit Tests
- `tests/test_pose_recovery.py` — `displacement_to_pose()` returns the correct NED/up
  scale when `entry.altitude` equals the ground datum; off-center displacement maps to
  metres without bias.
- `tests/test_localizer.py` — packaged localizer succeeds under both FLANN/LSH and
  BoVW coarse retrieval modes, and fails clearly for a misconfigured BoVW selection.
- `tests/test_retrieval.py` — backend selection, fallback behavior, and BoVW
  missing-index failure paths.

### Integration Tests
- Altitude-consistency guard: load the built `qau_campus.vnsdb` and assert every
  `entry.altitude` equals the configured `geo_reference.origin_altitude` (550 m), so a
  reverted/capture-altitude tag (600–620 m) cannot silently regress.
- `tests/test_runtime.py` — packaged runtime consumes the configured retrieval
  mode and localizes through the packaged path without invoking legacy script code.

### Simulation Tests
- In the map-only localization launch, off-center matches (e.g. grid_nw / grid_se)
  produce a global pose whose horizontal error is within tolerance, confirming the
  scale term is no longer compressed.
