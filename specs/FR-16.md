# FR-16: Visualisation

## Requirement
> The system shall visualise the navigation state, matched reference images,
> feature correspondences, and position error in real-time or post-hoc.

## Rationale
Post-hoc evaluation and visualization depend on a stable log format emitted by the
runtime path that operators actually launch. Even when real-time visual overlays are
handled elsewhere, the packaged ROS node must produce report-ready records that keep
estimated pose, ground truth, and navigation status aligned over time.

## Acceptance Criteria
1. **[Met]** The main ROS runtime emits JSONL evaluation logs suitable for
   post-hoc visualization and accuracy reporting.
2. **[Met]** Logs include estimated pose and ground-truth pose when ground truth is available.
3. **[Met]** The accuracy-report generator can consume the produced logs without schema conversion.
4. **[Met]** Logging remains optional and does not interfere with normal runtime behavior.
5. **[Met]** The runtime continues to operate if the ground-truth topic is unavailable.
