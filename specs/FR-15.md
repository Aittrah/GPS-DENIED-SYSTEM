# FR-15: Model Evaluation

## Requirement
> The system shall evaluate navigation accuracy against ground truth and generate
> accuracy reports including position error statistics and match confidence histograms.

## Rationale
Ground-truth evaluation is the only reliable way to quantify whether the packaged
runtime is producing usable navigation estimates in simulation. The ROS node that
launch files actually run must therefore be able to emit stable machine-readable
logs that the existing accuracy-report tooling can consume without depending on the
legacy script runtime.

## Acceptance Criteria
1. **[Met]** The main ROS runtime path (`src/vns/core/vns_node.py` ->
   `src/vns/core/runtime.py`) can emit JSONL evaluation logs when enabled.
2. **[Met]** Each evaluation record includes estimated pose, ground-truth pose when
   available, GNSS state, vision confidence, localization status, and a timestamp.
3. **[Met]** The generated JSONL remains compatible with
   `simulation/scripts/generate_accuracy_report.py` and
   `src/vns/validation/accuracy_report.py`.
4. **[Met]** Evaluation logging remains optional and does not break normal runtime
   operation when disabled or when the log file cannot be opened.
5. **[Met]** The runtime continues operating when the configured ground-truth topic is
   unavailable; logs may omit error metrics or record `ground_truth` as unavailable.

## Dependencies
FR-12, FR-14

## Linked Source Files
- `src/vns/core/vns_node.py` — subscribes to simulation topics and emits evaluation samples from the packaged ROS node.
- `src/vns/core/runtime.py` — stores the latest ground-truth pose in the packaged runtime state.
- `src/vns/validation/jsonl_logger.py` — reusable JSONL schema builder and writer for evaluation logs.
- `src/vns/validation/accuracy_report.py` — consumes evaluation JSONL and generates aggregate reports.
- `simulation/scripts/generate_accuracy_report.py` — CLI wrapper for the accuracy-report pipeline.
- `simulation/config/simulation.yaml` — enables and configures packaged evaluation logging in simulation.

## Test Plan

### Unit Tests
- Verify the JSONL logger writes legacy-compatible flat fields plus packaged-runtime status fields.
- Verify the logger records null error metrics when ground truth is unavailable and estimate-only logging is enabled.
- Verify logger initialization/write failures degrade to warnings without raising.

### Integration Tests
- Generate a temporary JSONL file from packaged runtime results and confirm
  `load_and_generate_report()` produces JSON and Markdown reports.
- Confirm report generation ignores estimate-only rows with null error fields instead
  of counting them as zero-error samples.

### Simulation Tests
- Run the launch-used ROS node with simulation logging enabled and confirm
  `logs/ground_truth_*.jsonl` is produced while `/vns_drone/ground_truth` is available.
